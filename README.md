# DayFlow Ultimate 5.0

**DayFlow** — күн тәртібін жоспарлауға арналған, толық қазақ тіліндегі, адаптивті веб-қосымша. Жоба HTML5, CSS3, Vanilla JavaScript және Nginx арқылы жасалған. Сайтқа Firebase Authentication арқылы кіресіз. Жоспарлар Cloud Firestore-да аккаунт бойынша сақталады.

## Негізгі мүмкіндіктер

- **Басты бет:** сәлемдесу, ағымдағы күн/уақыт, тапсырмалар саны, күндік прогресс, келесі істің басталуына қалған уақыт, мотивация.
- **Күнделікті тұрақты жоспар:** 9 бастапқы күнделікті тапсырма (ояну, жаттығу, тамақ, оқу, үй тапсырмасы, спорт, демалыс және ұйқыға дайындалу). Олар келесі күндері автоматты түрде қайта көрсетіледі; жаңа тапсырма қосылса да жоғалмайды.
- **Қайталану режимдері:** бір рет, күн сайын, жұмыс күндері, апта сайын; қажет болса соңғы күнді енгізуге болады.
- **Әр күнге бөлек орындалу белгісі:** бүгінгі істі аяқтау ертеңгі істі аяқталды деп белгілемейді.
- **Тапсырмалар:** қосу, өңдеу, толық жою, қайталанатын тапсырманы тек бір күннен алып тастау, категория/маңыздылық, іздеу, күн/мәртебе/санат бойынша сүзгі.
- **Қабаттасу ескертуі:** уақыттары қақтығысса хабарлайды, бірақ сақтауға мүмкіндік береді.
- **Күн тәртібі:** 24 сағаттық визуалды шкала, күндерді ауыстыру, өңдеу.
- **Күнтізбе:** айлар арасындағы ауысу, күнді таңдау, тапсырмалар индикаторлары.
- **Әдеттер:** жаңа әдет, өңдеу, жою, апталық белгілеу, соңғы 28 күн тарихы.
- **Статистика:** соңғы жеті күннің графиктері, санаттар және әдеттер нәтижелері.
- **Фокус таймері:** 15, 25 және 45 минут, 5 минуттық үзіліс, бастау/тоқтату/қайта бастау.
- **Ескертулер:** тапсырма басталғанда және дедлайнға 0/5/10/15/30/60 минут қалғанда сайт ішінде хабарлама; қолданушының таңдауы бойынша дыбыстық сигнал және браузер хабарламасы.
- **Баптаулар:** пайдаланушы атын өзгерту, ашық/қараңғы режим, дыбыс және ескертулерді қосу/сөндіру, JSON экспорт/импорт, барлық жазбаларды тазарту.
- **Бейімделген дизайн:** компьютер, планшет және телефон; анимациялар және қозғалысты азайтуды сұрайтын жүйелік баптауды қолдау.

## Firebase баптау

1. Firebase Console-де жоба ашып, **Project settings → Your apps** бөлімінде Web app тіркеңіз. Берілген веб-конфигурацияны `firebase-config.js` ішіне қойыңыз. Service account кілтін жобаға қоспаңыз.
2. **Authentication → Sign-in method** бөлімінде **Email/Password** әдісін қосыңыз.
3. **Firestore Database → Create database** бөлімінде әдепкі дерекқорды жасаңыз. **Rules** бөлімінде `firestore.rules` мазмұнын жариялаңыз. Бір Firebase жобасын бірнеше қолданба пайдаланса, DayFlow ережелерін қолданыстағы ережелермен біріктіріңіз.
4. Сайтты веб-сервер арқылы ашып, жаңа аккаунт тіркеңіз. Тапсырма қосып, Firestore-ға сақталғанын күтіңіз. Бетті қайта жүктеп, тапсырма көрінетінін тексеріңіз.

Бөлек Firebase жобасы үшін ережені CLI арқылы да жариялауға болады.

```bash
npx firebase-tools login
npx firebase-tools deploy --only firestore:rules --project YOUR_PROJECT_ID
```

## Windows жүйесінде Docker Desktop арқылы іске қосу

1. [Docker Desktop](https://www.docker.com/products/docker-desktop/) орнатып, қосыңыз.
2. Бұрынғы `DayFlow` контейнері іске қосылған болса, **сол контейнерді** тоқтатыңыз. Жаңа архивті басқа папкаға шығарыңыз.
3. `DayFlow` папкасын ашыңыз.
4. Папка ішінде терминал немесе PowerShell ашыңыз.
5. Қолданбаны жинап, іске қосыңыз:

   ```powershell
   docker compose up -d --build
   ```

6. Браузерден ашыңыз: **http://localhost:8080**
7. Контейнер күйін қараңыз:

   ```powershell
   docker compose ps
   ```

8. Логтарды қараңыз:

   ```powershell
   docker compose logs -f dayflow
   ```

9. Healthcheck: **http://localhost:8080/health** (`OK`, HTTP 200).
10. Контейнерді тоқтату:

    ```powershell
    docker compose down
    ```

11. Код өзгергеннен кейін қайта жинау:

    ```powershell
    docker compose up -d --build
    ```

**Маңызды:** сайтқа кіргенде ескі дизайн көрсетілсе, `Ctrl + Shift + R` басыңыз. Жаңа нұсқада CSS/JS файлдары нұсқаланып қосылған және Nginx оларды ұзақ кэштемейді.

### Егер ескі контейнермен атау қақтығысы болса

Бұл командаларды орындау ескі іске қосылған жобаны тоқтатуы мүмкін; қажет болса алдымен оның деректерін JSON-ға экспорттаңыз.

```powershell
docker rm -f dayflow-app
docker compose up -d --build
```

### Егер Docker Desktop қосылмаған болса

Docker Desktop-ты іске қосыңыз және Linux containers / WSL 2 дұрыс жұмыс істейтінін тексеріңіз. Содан кейін `docker compose up -d --build` командасын қайталаңыз.

### Егер 8080 порты бос болмаса

`compose.yaml` файлының `ports` бөлімін өзгертіңіз:

```yaml
ports:
  - "8081:80"
```

Осыдан кейін сайт `http://localhost:8081` арқылы ашылады.

## Телефонда ашу

Ноутбук пен телефон бір Wi-Fi желісінде болсын. Windows-та `ipconfig` командасы арқылы Wi-Fi IPv4 мекенжайын табыңыз. Мысалы, ноутбуктың IP адресі `192.168.1.105` болса, телефон браузеріне `http://192.168.1.105:8080` енгізіңіз. Windows Firewall тиісті портқа рұқсат беруі керек. Ноутбук пен Docker қосулы болуы тиіс.

**HTTPS және қауіпсіз контекст:** жай HTTP жергілікті IP-адресте браузердің жүйелік Notification API-і жұмыс істемеуі мүмкін. Қоғамдық интернетке жариялау үшін HTTPS қолдану ұсынылады. `.kz` домені үшін қолданыстағы қазақстандық хостинг талаптарын бөлек тексеріңіз.

## Ескертулер мен будильник туралы маңызды ақпарат

Бұл нұсқада backend, push сервер және service worker арқылы фондық push-жеткізу жоқ. Сондықтан:

- Сайт **ашық тұрған кезде** JavaScript таймері тапсырма басталғанда және дедлайн жақындағанда ескерту көрсетеді.
- Дыбыстық сигнал үшін браузерде пайдаланушы әрекеті болуы және құрылғы дыбысы қосулы болуы мүмкін.
- Жүйелік браузер хабарламасы үшін сайттың HTTPS (не `localhost`) арқылы ашылуы және пайдаланушының хабарламаға рұқсат беруі қажет.
- Браузер **толық жабық тұрса**, компьютер ұйқы режимінде болса немесе телефон фондық вкладкаларды тоқтатса, ескертудің нақты уақытта келетініне кепілдік жоқ.
- Ескертуді «Баптаулар» ішіндегі **Ескертуді тексеру** және **Дыбысты тексеру** батырмаларымен тексеріңіз.

## Деректерді сақтау және жаңа нұсқаға көшу

Бір аккаунтпен кіргенде Firestore-да сақталған жоспарлар басқа құрылғыда да ашылады. Соңғы нұсқаны алу үшін бетті қайта жүктеңіз. Басқа құрылғы жоспарды өзгертіп үлгерсе, DayFlow кейінгі сақтаумен сол өзгерісті үстінен жазбайды. Мұндайда жергілікті өзгерістерді JSON-ға экспорттап, бетті қайта жүктеуге болады.

Бұрын осы браузерде сақталған жоспарды аккаунтқа көшіру үшін **Баптаулар → Браузердегі ескі деректі көшіру** батырмасын басыңыз. Растағаннан кейін ескі жазбалар аккаунттағы қазіргі жоспарды алмастырады.

Сақтық көшірме алу үшін **Баптаулар → JSON экспорт** батырмасын пайдаланыңыз. Қалпына келтіру үшін **JSON импорт** таңдаңыз. Файл құрылымы тексеріледі; қате JSON бар деректерді өзгертпейді. Барлығын өшіргеннен кейін демо тапсырмалар автоматты қайта қосылмайды.

## Тестілеу және шектеулер

Кодқа `node --check app.js` синтаксистік тексерісі жүргізілді. Nginx конфигурациясы `nginx -t` арқылы тексерілді және жергілікті Nginx сервері `/`, `index.html`, `style.css`, `app.js`, `manifest.webmanifest`, `assets/favicon.svg`, `/health` сұраныстарына HTTP 200 қайтарды. Playwright + Chromium арқылы интерфейс, қосу/өңдеу/жою, күнделікті қайталану, күнтізбе, іздеу, сүзгілеу, әдеттер, статистика, қате JSON, дұрыс JSON қалпына келтіру, ескі деректерді көшіру, 320–1440 px экрандар және уақытты имитациялау арқылы ескертулер тексерілді.

**Docker Desktop контейнерінің өзі осы әзірлеу ортасында іске қосылмады** — оны Windows компьютерінде жоғарыдағы командалармен тексеріңіз. Жүйелік Notification API-дің нақты телефондағы фондық жұмысы браузерге тәуелді және бөлек тексеріледі.
